# 見直しのしくみの数値を、1 つずつ変えて見る

夜のすごし方を見直すしくみの数値は、すべて仮置きです（[GentlePolicy.java](../../src/main/java/app/yurune/constant/GentlePolicy.java)）。仮置きの数値のまわりで、結果がどう動くかを、シミュレーションで調べました。調べたのは 2026-10-13 です。

この調べ方から、「いまの値が正しい」とは言えません。わかるのは、値を変えたときに、結果がどちらへ動くかだけです。

## 調べ方

1. `GentlePolicy.java` の数値を 1 つだけ変える。
2. `mvn test -Dtest=PdcaSimulationTest` を実行する。
3. 書き出される `target/pdca-sim-report.txt` を読み、元に戻す。

シミュレーションは、寝かたの違う利用者を 200 人ずつ作り、84 夜（シナリオによっては 42 夜）のあいだ、しくみを動かします。シナリオ（S1〜S9）と、結果を判定する基準は、[Scenarios.java](../../src/test/java/app/yurune/pdca/Scenarios.java) にあります。基準は、結果を見る前に置いたもので、結果に合わせて変えていません。種を固定しているので、同じ値なら、同じ結果が出ます。

## 結果

## わかったこと

- **いまの値は、基準を満たしていません。** 12 個のうち 5 個しか満たしていません。満たしていない 7 個は、S1、S2、S3（外せた割合）、S4、S5（2 つ目）、S6、S7 です。この結果は、基準を見直さずに、そのまま残してあります。
- **水準を動かすと、見つける力と、誤って見つける割合が、いっしょに動きます。** 0.025、0.05、0.10 の順に、S1 は 57.5、64.0、70.0、S2 は 8.5、13.0、18.5、S4 は 14.0、18.5、28.5 でした。どちらを大事にするかの問題で、この試験では、正しい値は決まりません。
- **対照の間隔を 2 夜に 1 夜にすると、誤って見つける割合が減ります**（S2、S4 は基準の中）。S7 も増えますが、S1、S3、S6 が下がり、早い時期に見つける力も落ちます（28 夜の時点で 32.0 が 16.5）。
- **基準の夜を 14 にすると、遅くなります。** 28 夜の時点で見つけた割合は 9.0（いまの値は 32.0）、悪くなる人を戻せた割合は 5.5 になりました。5 にすると、早くなりますが、S4 が 21.5 に増えます。
- **最小の夜数と、見直しの間隔は、あまり動きません。** S1 は 58.5〜65.5、S2 は 10〜13 の範囲でした。
- **S6、S7、S5 の 2 つ目は、どの値でも、基準に届きませんでした**（S6 の最高は 30.0、S7 は 33.0、S5 の 2 つ目は 44.0）。数値ではなく、規則の作りに原因があるように見えますが、調べていません。
- **S1 の曲線は、56 夜のあとは、ほぼ平らです。** どの値でも、3〜4 割の利用者は、84 夜のうちに、差のある音を見つけられていません。
- 全体として、ほかの値のほうがよい、とは言えません。水準 0.025 は、満たした数が 8 で、いちばん多いのですが、S1 と S7 を下げて、S2 と S4 を上げた分です。

## 使えない言い方

- 200 人での 1 つの割合の誤差は、2.5〜3.5 ポイントほどです。4〜5 ポイント以内の違いは、読めません。
- シミュレーションの利用者（寝つきの長さ、夜ごとのばらつき、「合っていた」と答える確率、日ごとの傾向）は、すべて仮定です。実際の人のデータは、使っていません。
- この結果は、アルゴリズムの動きを見るためのもので、実際の人に役立つことを示すものではありません。
